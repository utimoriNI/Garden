# 開発日誌：Bookmark Sort MVP

## 2026年9月8日〜9日

### 目的

X（Twitter）の「いいね」と「ブックマーク」を取得し、内容を確認しながら以下の保存先へ整理できる個人用Webアプリを構築する。

- Eagle
- Raindrop.io
- Google Maps
- 破棄

### 実施内容

空のリポジトリからBookmark SortのMVPを実装した。

主な機能は以下のとおり。

- Xの「いいね」「ブックマーク」の取得
- 同一投稿の重複排除
- 古い投稿から1件ずつ処理するキュー
- OpenAIによる保存先候補の分類
- AI提案をユーザーが変更できる確認画面
- Eagleへのメディア保存
- Raindrop.ioへのリンク・手動タグ保存
- Google Placesによる店舗候補検索
- Google Mapsを開いて手動保存する導線
- 投稿の破棄
- 直近10件の処理履歴
- 処理済み投稿の再オープン
- キーボードショートカット
- WebMCPによる同期・保存先変更・破棄操作
- D1データベースへの状態保存

### X API対応

以下の公式APIを利用する設計とした。

- いいね一覧
- ブックマーク一覧

必要なOAuth 2.0スコープは以下。

```
tweet.read
users.read
like.read
bookmark.read
offline.access
```

`X_ACCESS_TOKEN` に設定する値はConsumer Keyではなく、OAuth 2.0 PKCEで発行されたUser Access Tokenである。

`X_USER_ID` には数値形式のXユーザーIDを設定する。

調査の結果、現在の実装は発行済みAccess Tokenを環境変数から読み込む方式であり、Xログイン機能自体はまだ実装されていないことを確認した。

今後Xログインをアプリへ組み込む場合は、以下が必要になる。

- OAuth認可開始エンドポイント
- OAuthコールバックエンドポイント
- PKCEの`code_verifier`とS256 `code_challenge`
- `state`によるCSRF対策
- 認可コードとAccess Tokenの交換
- Refresh Tokenの保存と自動更新
- ユーザーごとのトークン管理

X Developer Consoleへ登録する情報は以下を想定している。

ウェブサイトURL：

```
https://bookmark-sort.royalbread-256.chatgpt.site
```

コールバックURI：

```
https://bookmark-sort.royalbread-256.chatgpt.site/api/auth/x/callback
```

ただし、コールバック処理は現時点では未実装である。

### 外部サービス対応

#### Eagle

Eagle 4.0 Build 21以降のローカルWeb APIを利用する。

ホストされたWebサイトから`localhost:41595`へアクセスするため、ブラウザのCORSやPrivate Network Access制限を受ける可能性がある。失敗時は投稿を処理済みにせず、再試行できる状態を維持する。

将来的にはブラウザ拡張またはローカルコンパニオンアプリの導入を検討する。

#### Raindrop.io

REST APIを使用し、「未整理」コレクションへ保存する。

タグはAIで自動生成せず、ユーザーが入力したものだけを送信する設計とした。

#### Google Maps

Google Places API (New)で店舗候補を検索する。

Google Mapsの個人用保存リストへ直接追加する公開APIがないため、候補確認後にGoogle Mapsを開き、ユーザーがMaps上で最終保存する方式とした。

#### OpenAI

Responses APIとStructured Outputsを使用し、分類結果を以下の3種類に限定する。

```
EAGLE
RAINDROP
GOOGLE_MAPS
```

具体的な店舗情報がない状態でGoogle Mapsが選択された場合は、アプリ側の検証でRaindropへ戻す。

### 公開方針

現状のアプリは単一ユーザー向けで、データベースと外部サービストークンをユーザー別に分離していない。

そのため、実データ用のAPIキーを設定した状態で一般公開すると、第三者が以下を実行できる可能性がある。

- Xの保存済み投稿を閲覧
- 同期処理を実行
- 投稿を処理・破棄
- 所有者のRaindropアカウントへ保存

現時点で安全な運用方法は以下のいずれか。

1. Mockデモとして一般公開する
2. 実データ版はオーナー限定で利用する

複数ユーザー向けに一般公開する場合は、ログイン、OAuth、ユーザー別データ分離、権限制御、レート制限の追加が必要になる。

### 本番環境変数

実サービスへ接続する場合は、Sitesの本番環境変数へ以下を登録する。

```
X_ACCESS_TOKEN
X_USER_ID
OPENAI_API_KEY
OPENAI_MODEL
RAINDROP_ACCESS_TOKEN
RAINDROP_COLLECTION_ID
GOOGLE_PLACES_API_KEY
```

必須度は利用するサービスによって異なる。未設定のサービスはMockモードで動作する。

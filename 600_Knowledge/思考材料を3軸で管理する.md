# 思考材料を3軸で管理する

## 要旨

リーディングノート、自分の思いつき、Raindropから取り込んだ情報を、完全に別の箱として扱うと、考えるときに材料が分断される。

そこで、ノートを一つの分類だけで整理するのではなく、次の3軸で捉える。

1. **起源**：どこから来た情報か
2. **構造**：どのような役割のノートか
3. **状態**：整理の進み具合はどうか

保存時には区別し、一覧・思考時には必要に応じて統合する。

> [!important] 基本原則
> 「保存上は分けるが、思考上はまとめて見る」。
> Reading Noteと自分の考えを同じ種類のノートに偽装するのではなく、異なる属性を持つ思考材料として同じ一覧に載せる。

## 3つの軸

| 軸 | 例 | 役割 |
| --- | --- | --- |
| 起源 | `self` / `web` / `book` / `raindrop` / `kindle` | 何をきっかけに生まれたかを記録する |
| 構造 | `thought` / `reading-note` / `knowledge` / `moc` | ノートがどの段階・役割にあるかを表す |
| 状態 | `raw` / `review` / `draft` / `published` | 運用上の進捗を表す |

### 起源

起源は、そのノートの出どころを表す。

- `self`：自分の思いつき、経験、観察
- `web`：Web記事やSNS以外のWeb情報
- `book` / `kindle`：本やKindleのハイライト
- `raindrop`：Raindropに保存したWeb情報や投稿

起源は、ノートの価値や正しさを表すものではない。自分の考えであっても、Raindropの投稿をきっかけに生まれた場合は、起源を`raindrop`としてよい。

### 構造

構造は、ノートがどのような形をしているかを表す。

- `thought`：自分の思いつきや観察
- `reading-note`：外部の文章・発言・場面など、自分に示唆を与えた一節
- `knowledge`：複数の材料を整理し、自分の考えとして形にしたもの
- `moc`：複数のノートを見渡すための入口

`reading-note`は、単なる引用の保管場所ではない。引用に対する共感、違和感、反論、疑問も同じノートに残してよい。

例えば次のように、元の刺激と自分の反応を併記する。

```markdown
---
type: reading-note
origin: raindrop
status: review
---

# 元の発言・引用

> 印象に残った文章

## 自分の反応

なぜ気になったのか、共感したのか、違和感があるのかを書く。

## 問い

この内容についてまだ考えたいことを書く。
```

### 状態

状態は、内容の完成度ではなく、次に何をするかを表す。

- `raw`：入力したばかりで未整理
- `review`：一覧・Canvasで見直す対象
- `draft`：KnowledgeやMOCとして文章化中
- `published`：見返す形に整え、静的HTMLなどに公開可能

状態は後から変更する。最初から正しい構造やタグを決める必要はない。

## 思考材料を統合して見る

思考時には、次の条件に該当するノートを一つの一覧にまとめる。

```text
構造が thought または reading-note
かつ状態が raw または review
```

この一覧には、次のようなノートが同時に表示される。

- ふと思いついたこと
- 本から得た一節
- Raindropに保存した投稿
- Web記事を読んで感じた違和感
- 既存のReading Noteに書いた自分の反応

ここでは起源や構造で分離するのではなく、「今、自分が考える材料になるか」を基準にする。

## 入力からKnowledge化まで

```text
Raindrop・音声入力・日常の思いつき
        ↓
統合された思考材料一覧
        ↓
Canvasで関係性・疑問・反例を整理
        ↓
Codexで論点を抽出し、Markdownの初稿を作る
        ↓
KnowledgeまたはMOCとして保存
        ↓
必要なものだけ静的HTMLに公開
```

### フリーティング

フリーティングは、最初から一つひとつファイルに分けない。

日次または週次のログに追記し、後から独立した主張だけを`thought`ノートとして切り出す。

```markdown
# 2026-07-31 思いつきログ

## 09:12

ふと思ったこと。

## 11:40

別の思いつき。
```

入力時は連ね、再利用したい段階で分ける。これにより、音声入力の速度と、後から検索・再利用できる粒度を両立する。

### Raindrop

Raindropに保存した情報をすべてObsidianに複製するのではなく、「Obsidianで考えたいもの」だけを取り込む。

```text
Raindropで保存
  ↓ Obsidian用タグを付ける
Obsidianの300_Inputへ取り込む
  ↓ origin: raindrop を付ける
自分の反応・疑問を追記する
```

RaindropはWeb情報の保存場所、Obsidianは自分の文脈で考える場所として分担する。ただし、取り込まれたRaindropノートはReading Noteや自分のthoughtと同じ「思考材料一覧」に表示する。

### Canvas

恒久的なCanvasは「一つの問い」よりも「一つのテーマ」を単位にする。

- 全体像Canvas：生き方、他者、評価、学習など大きな領域を並べる
- テーマCanvas：評価と承認、能力主義など抽象的な論点を並べる
- 一時Canvas：具体的なthoughtやreading-noteを使って考える

恒久Canvasにすべての断片を置き続けない。断片がまとまったら、複数のノートを束ねるKnowledgeやMOCを作り、Canvas上ではその概念カードに置き換える。

Canvasは関係性を見る場所であり、Baseは一覧する場所、Markdownは考えを定着させる場所である。

## 3軸を使ったfrontmatterの例

### 自分の思いつき

```yaml
---
type: thought
origin: self
status: raw
---
```

### RaindropをきっかけにしたReading Note

```yaml
---
type: reading-note
origin: raindrop
status: review
---
```

### 整理した自分の考え

```yaml
---
type: knowledge
origin: self
status: draft
---
```

Knowledgeノートには、元になったノートへのリンクを残す。

```markdown
## もとになった思考材料

- [[元の思いつき]]
- [[Reading Note]]
- [[思考セッションCanvas]]
```

## この方法の利点

- 外部情報と自分の考えを混ぜずに保存できる
- それらを思考時には一つの一覧で見られる
- 入力時に分類を強制されない
- RaindropをWeb保存場所として使い続けられる
- Canvasの一覧性とMarkdownの検索性を両立できる
- Codexが扱う対象を、選択した思考材料に限定できる
- KnowledgeやHTMLにした後も、元の刺激と自分の反応を辿れる

## 運用上の判断基準

迷った場合は、次の順で判断する。

1. 今すぐ残す必要があるか。必要ならフリーティングに追記する
2. 後から独立して参照したいか。必要なら`thought`または`reading-note`にする
3. 複数の材料をつないだ自分の主張になっているか。なっていれば`knowledge`にする
4. 複数のKnowledgeやReading Noteを見渡す必要があるか。必要なら`moc`にする

分類を正しく決めることより、思考材料を失わず、後から同じ一覧に戻せることを優先する。
